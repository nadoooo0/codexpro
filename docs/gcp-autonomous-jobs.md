# GCP의 승인된 작업과 장시간 명령

이 수정판은 GitHub의 CodexPro 0.30.0에 적용한 MCP 연결 개선이다. GPT 모델을 실행·대체하거나 별도 AI에게 작업을 위임하지 않는다.

## 설정

```sh
CODEXPRO_BASH_MODE=full
CODEXPRO_WRITE_MODE=workspace
CODEXPRO_MAX_BASH_TIMEOUT_MS=0
CODEXPRO_HTTP_SESSION_TTL_MS=0
CODEXPRO_TOOL_CARDS=0
```

- `full`은 사용자가 승인한 셸 구문을 허용한다. `safe`의 명령 허용 목록을 계속 적용하지 않는다. 선택된 full 모드 자체는 자가 검사 실패·경고로 표시하지 않는다.
- 최대 명령 시간 `0`은 서버의 실행 마감 시간을 해제한다. 이때 출력 수집 한도에 도달해도 명령을 종료하지 않고 초과 출력을 버리며 `truncated: true`로 표시한다.
- HTTP 세션 만료 `0`은 시간에 따른 세션 정리를 끈다. 수용량 제한에 따른 오래된 세션 제거와 실제 프로세스 재시작은 별도이며, 작업 기록은 MCP 세션과 별도로 보존한다.
- 인증 토큰은 계속 필요하다. 앱 권한과 모델의 대화상 허락 요청을 구분하며, 승인된 작업에 대해 같은 허락이나 막연한 경고를 반복하도록 지시하지 않는다. 실제 오류·비밀 공개·무관한 작업·외부 전송·비용 발생의 범위를 숨기거나 확대하지 않는다.
- **CodexPro는 모델 추론 시간을 정하지 않는다.** 위 설정은 이 프로그램의 명령·연결 제한을 해제한다. ChatGPT 플랫폼 자체의 추론·대화·요금·안전 정책을 바꾸었다는 뜻이 아니다.

`server_config`의 `tool_contract_revision`이 `gcp-autonomous-jobs-v1`인지 확인하면 수정 계약이 실제 호출 대상에 반영됐는지 구별할 수 있다. 파일만 바꾸었거나 앱 설명이 오래된 상태를 실제 반영으로 취급하지 않는다.

## 실행·재조회

```json
{"command":"sleep 35; printf completed", "background":true, "request_id":"verify-long-1"}
```

`bash`는 즉시 `running` 기록을 반환한다. 실행 전에 정한 같은 `request_id`를 `bash_status`에 전달한다. 결과를 받지 못했다면 새 ID로 명령을 제출하지 말고 원래 ID와 원래 작업 폴더로 상태부터 확인한다.

- 동일 ID와 동일 명령·작업 폴더·실행 조건의 재요청은 기존 기록을 반환한다. 다른 입력으로 같은 ID를 재사용하면 새 실행 없이 오류를 반환한다.
- 기록은 사용자 전용 디렉터리에 남긴다. 실행 중 서버가 재시작되면 기존 ID는 `unknown`으로 반환하며 자동으로 다시 실행하지 않는다. 이는 실행을 복원했다는 뜻이 아니다. 기존 파일·프로세스 상태를 확인해 복구 여부를 판단해야 한다.
- `bash_status`는 읽기 도구이며 결과를 소비하지 않는다. 완료 출력은 반복해서 같은 내용으로 조회할 수 있다. `truncated`라면 전체 출력이 아니다.
- `bash_cancel`은 같은 ID의 현재 프로세스에만 종료를 요청한다. 종료 요청을 완료라고 말하지 말고 `bash_status`에서 최종 상태를 확인한다.
- 명시적으로 `timeout_ms`를 전달하면 해당 명령에는 마감 시간이 생긴다. 실행 중·성공·실패·시간 초과·취소·상태 불명은 별도로 표시한다. 동기식 명령의 실패도 MCP `isError`로 반환한다.
- 성공한 명령의 종료 코드만으로 전체 사용자 작업의 완료를 선언하지 않는다. 파일 수정은 다시 읽어 확인한다.

## 검사와 운영

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run build
node scripts/autonomous-jobs-smoke.mjs
node scripts/http-smoke.mjs
node scripts/smoke.mjs
```

자율 작업 검사는 30초 초과 실행, 파일 생성·수정·재읽기, 결과 재조회, 같은 요청 재전송 시 중복 실행 방지, 새 MCP 연결, 새 프로세스의 불명 상태, 취소, 명시적 시간 초과, 출력 잘림, 없는 파일 및 잘못된 요청 오류를 확인한다. 일반 smoke의 프로세스 트리 종료 검사는 혼잡한 VM에서 계측용 자식 Node가 시작될 시간을 확보한 후 제한 시간 종료를 검사한다.

GCP 운영에서는 기존 VM의 HTTPS 프록시를 사용할 수 있다. 다른 서비스를 재시작하지 않고 해당 설정을 백업·검증한 후 정상적인 설정 재적용으로 경로를 추가한다. 서비스는 한 개만 실행하고, 토큰·작업 기록·실제 연결 URL을 Git에 커밋하지 않는다. 앱의 도구 정보 갱신·실제 Pro 사용 시험은 로컬 검사와 별도로 수행한다.
